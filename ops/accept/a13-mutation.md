# A13 变异抽检(人工完成项,由主代理执行)

A13 不是脚本:它要求主代理对 5 处关键逻辑各做一次变异,**每一处都必须让测试变红**,再把代码还原。
`ops/accept-p0.sh --list` 与汇总里 A13 恒显示为【人工完成项】,状态由下面的标记文件决定;没有有效标记就按「未执行(4)」计入失败汇总。

## 5 处变异点

| 编号 | 位置                                     | 变异示例                                | 应变红的测试             |
| ---- | ---------------------------------------- | --------------------------------------- | ------------------------ |
| M1   | 预算比较符(`src/budget/budget.ts`)       | 把「严格大于」改成 `>=`,或反过来        | `test/budget`            |
| M2   | G2 判断(`src/guards/g2.ts`)              | 让内容 PR 改 `status` 也放行            | `test/guards/g2.test.ts` |
| M3   | 脱敏第二遍复扫(`src/redact/redactor.ts`) | 跳过第二遍,或让第二遍命中时不拒绝       | `test/redact`、A3        |
| M4   | reader 工具失败计数(`src/readers/**`)    | 失败计数恒为 0,或把成功的结果也算失败   | `test/readers`、A6       |
| M5   | snapshot 比对(`ops/lib/snapshot.mjs`)    | 让 `diffSnapshots` 对内容变化返回空差异 | `test/ops`、A5 自检      |

具体行号以当时的代码为准,变异点可在同一函数内另选,但五类逻辑各一处,不可缺。

## 做法(防止「变异没生效却显示绿」)

1. 先在**未变异**的树上跑对应测试,确认基线是绿的(否则「变红」不能说明任何事)。
2. 变异前 `cp <文件> <文件>.mut-bak`(**不要用 `git checkout` 还原**:会丢掉未提交的改动)。
3. 用脚本做替换并**先断言匹配次数恰好为 1**(0 次 = 变异没落到代码上,多次 = 改多了),再跑测试。
4. 红的判据:测试进程非零退出,**并且**失败信息指向被变异的行为(不是语法错误、不是工具没启动)。
5. 用 `cp <文件>.mut-bak <文件>` 还原,删掉备份,再跑一次对应测试确认回到绿。
6. 涉及 `dist/` 的测试(跨包读 dist)变异后要先 `pnpm run build`,还原后再 build 一次,否则会假阴性。
7. 对写入出口守卫做变异时用临时假 HOME,断言真实 HOME 前后无变化。

## 标记文件

5 处都变红、已还原、基线重新为绿之后,写 `.state/accept/a13.done`(已被 gitignore,不入库),**内容恰好如下**(`#` 开头的行与空行忽略):

```
head: <当前 HEAD 的 40 位提交 SHA>
result: 5/5 red
M1: red
M2: red
M3: red
M4: red
M5: red
```

- `head:` 必须等于当前 `git rev-parse HEAD`。**提交之后标记就过期**(状态显示「未做」,detail 为 stale):A13 要在最终提交之后做、或提交后重做。
- 缺任何一行、多出任何内容、`result` 不是 `5/5 red`,一律按无效处理。
- 标记只是「主代理声明做过」的凭据,不替代上面的做法;验收汇报里仍应逐处写出变异位置与失败信息。
