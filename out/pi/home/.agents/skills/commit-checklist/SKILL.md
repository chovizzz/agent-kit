# 提交前自检清单

在宣布完成之前,逐项确认:

1. 运行项目的全量检查(类型检查、测试、静态检查、格式检查),读退出码与失败摘要,不只看输出末尾。
2. 查看变更清单:只包含任务必需的文件,没有无关的格式化或顺手修改。
3. 对新增内容做密钥模式扫描:令牌、口令、私钥不得出现在源码、样例配置、提交说明或日志里。
4. 质量门禁(只查本次改动涉及的文件,在项目跑测试的那台机器上跑):
   - 范围:三个工具的 --changed 取自 git status,只包含未提交的新增与修改文件,按文件筛选。改动已经提交、或在干净检出里跑时,它会查不到东西;这时用 git diff --name-only <基线>...HEAD 列出文件,作为参数传入,并在汇报里写明基线。范围为空不等于通过。
   - crapper:CRAP 不低于 10 的函数,拆分或补测试。
   - dryer:结构相似度不低于 0.8 的重复(其默认阈值是 0.82,要显式传 --threshold 0.8),消除。
   - mutator:存活的变异体补测试杀掉,未覆盖的补覆盖,死代码删掉。
   - 超线项不修的,写明理由。工具不可用就写「未运行」及原因,不阻塞提交。
   - 这些工具会写 .metrics/、可能往依赖目录装覆盖率组件,mutator 运行期间会改源码:在含本次改动的独立副本里跑,不在共享检出里跑。跑完(包括中断后)核对源码与依赖只剩本次改动,只还原工具造成的变化,不要用无差别的 reset 或 clean;这些产物不提交。
   - 为门禁做了修改,就重跑第 1–3 步。
5. 汇报时写明:跑了哪些检查、各自的退出码、门禁范围与结果、尚未解决的问题。
