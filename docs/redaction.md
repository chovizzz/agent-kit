# 脱敏模块(B09)

对应设计 §6.3、§9,计划 B09 / A3 / A10。本文只描述**已实现**的行为;做不到的单列在「已知缺口」,不写成"支持"。

代码:`src/redact/**`(引擎、规则、种子集、自检),命令 `src/commands/redact-cmd.ts`(`agent-kit redact`),测试 `test/redact/**`。
接口是冻结契约 `src/contracts/redact.ts` 的 `Redactor`(`pass1` / `pass2` / `apply`),工厂是 `createRedactor(config, options)`。

## 1. 流程

```text
输入文本
  │  长度 > max_input_chars  ──────────────────────────► fail-closed(error)
  ▼
pass1  归一化视图 → 剥合法占位符 → 规则 → 压缩视图(分行/拼接)→ 解码(深度 ≤2)→ 合并重叠区间 → 替换
  │
  ▼
pass2  对 pass1 的输出再扫一遍(同一引擎,解码深度 ≤3);任何命中 ⇒ 不干净
  │
  ▼
apply  pass1 + pass2;残留 / 异常 / 超时 ⇒ { ok:false, reason } ,调用方丢弃整条信号,命令退出 3
```

- **丢弃的粒度**:`apply` 失败时调用方丢弃**整条信号**(契约语义)。`pass1` 本身只替换命中的区间,不丢整条。
- **pass2 不是独立复核**:它与 pass1 共用同一套规则,所以同一条规则的 bug 会在两遍里各犯一次。它的实际增量是三样:
  解码深度多一层(嵌套编码)、把合法占位符剥掉后重新拼起来扫(占位符把秘密从中间切开的情形)、对 pass1 自己的输出做一致性检查
  (pass1 输出里不该再有命中;有就说明 pass1 的区间合并或映射有 bug)。
  另外 pass2 带一组**独立写成的残留探测器**(`probe_*`:sk-、soh_、gh*\_、AKIA/ASIA、xox*、PEM 头+体;在 `engine.ts` 里,不 import `rules.ts`,不受规则禁用影响,且都不比 pass1 对应规则更宽),用来兜 pass1 某条规则本身出 bug 的情形;有测试证明禁用 `prefix_sk` 后 `apply` 仍返回 `residual`。JWT 因为需要手写扫描避免二次回溯,没有做独立探测器。放行决策必须落在 `apply` / pass2 的结果上,不能只信 pass1 的输出。
- **坐标系**:`pass1` 与 `pass2` 返回的 `Hit.start/end` 都是**该次调用输入文本**的 UTF-16 偏移(归一化、剥占位符之后仍映射回输入原文)。
  `Hit` 不含命中文本。
- **预算**:`timeout_ms`(默认 50)是**每次 `pass1` / `pass2` 调用各自**的预算,不是 `apply` 的总预算。
  `apply` 内部的 pass2 不再套 `max_input_chars`(pass1 的占位符会使文本变长),但时间预算照样生效。

### 3.1 凭据赋值:引用 vs 真值(B09b)

会话里常有只按名字读环境变量的命令(`grep '^FOO_SERVICE_TOKEN=' "$ENVFILE" | cut -d= -f2-`)。名字后面没有值,不是凭据。
下面三种情形按**引用**处理:不脱敏、不产生占位符、也不会在第二遍成为残留。其余一律按值处理(宁可多脱敏)。

1. **引用式**(`'^NAME='`、`"^NAME="`,含 JSON 转义的 `\"^NAME=\"`):`=` 之后紧跟的引号是**收尾**引号。四个条件缺一不可:
   - 该引号之前、键名之前有同种引号作开引号,开引号与键名之间只含 `[\w.^|(-]`(无空白、无别的引号),键名与 `=` 之间也不能有引号(`"NAME"="…` 里的引号是键名自己的);转义反斜杠数与收尾引号一致;
   - 同一行里该开引号之前、同种同转义深度的引号个数为偶数(`'x'NAME=' …'` 里 `NAME` 前的引号是 `'x'` 的收尾,奇偶会拦下);
   - 收尾引号之后是行尾 / 空白 / `| ; & < > )`,或 JSON 字符串的收尾引号(`"` 后跟空白 / `, } ] :` / 行尾);
   - 回看不超过 4096 字符(看不完就不当引用)。
     满足后,看收尾引号之后的**下一个词**(以引号开头的取到同种引号,否则取到空白 / `| ; & < >`,去两侧引号与转义反斜杠,不跨行):
     长度不足 8、或是**引用形状**就放行,否则只把这个词脱敏。
2. **占位符占了值的位置**:`NAME=` 与值之间(原文里)夹着合法占位符,且占位符之后是**边界**(空白;或引号,且引号后面紧跟空白 / 行尾 / 分隔符)→ 值就是那个占位符,后面的词(`NAME=[[REDACTED:credential]] https://…`)是别的东西。
   占位符之后**没有任何间隔**(`NAME=[[REDACTED:credential]]tail…`),或占位符后面的引号**紧跟值字符**(`NAME=[[REDACTED:credential]]"值"`,B09c:这是第一遍只脱敏了拼接值的前一截)则后面仍是值的一部分,照常判。其余情形一律按赋值处理(fail-closed)。
3. **值本身像引用**:见 §3.2「引用形态」(B09c 之前是 `looksNonSecret` 的前缀匹配,已被整词判据取代)。

**引用形状**(只用于上面第 1 条的「下一个词」,**白名单**,不匹配就当值):
`$VAR` / `${VAR}`(可带路径后缀);`$(…)` 与反引号开头;路径(有根标记 `/` `~/` `./` `../` `C:\` `\\`,至少两段,每段只含 `[\w.@+~-]`);
文件名(`.env` `.json` `.txt` `.yaml/.yml` `.conf` `.cfg` `.ini` `.log` `.sh` `.toml` `.pem` `.key` `.properties` `.secret(s)` `.local` `.sample` `.example` `.bak`);
命令行选项(长选项只认小写 kebab,如 `--no-color`;短选项只认 1-2 个字母或 `-f2-` 形;`--x=值` 的值部分要重新判,数字或引用形态才放行);以及 §3.2 引用形态里除 `$` `%` `<` `{` 开头之外的那些形状。

**判据里刻意不用什么**:不看熵、字符类、大小写。低熵口令(`correcthorsebattery`、`Summer2024x`)恰恰是最危险的一类,按「像不像秘密」放行会放过它们;
所以只认「长得像引用」的白名单,其它都脱敏。代价见 §7 已知缺口(`gap.word_after_name_quote`)。

被放行的匹配**不再吞掉后面的文本**:放行后从操作符之后继续扫,所以同一行里先有引用、后有真值,真值仍被脱敏。

**幂等与一致**:

- 放行的位置不产生占位符;占位符紧邻处按第 2 条判。`apply(apply(x)) == apply(x)`,且 `pass2(apply(x))` 干净(`test/redact/envref.test.ts` 用种子集 + 随机拼装文本验证,含无分隔拼接)。
- 值类规则不再把 JSON 转义的换行当成值的一部分(`view_json_ws`;原视图补扫里无引号值也在转义的 `\n` `\r` 处截断,见 §3.2),所以按行脱敏、整文件分块(64 KiB,重叠 2 KiB)脱敏、`redact --stdin --check` 对信号文件的复扫,与 collect 内部 pass2 对真换行文本的结论一致。
- `cred_cli_flag` 同样遵守第 2 条(`--token=[[REDACTED:credential]] https://…`);`cred_authz` 的值被转义引号截断后剩下的孤立反斜杠不再当成值。

### 3.2 值类规则的召回修复(B09c)

B09c 之前,`cred_assign` / `cred_cli_flag` / `cred_authz` / `cred_cookie` 用「前缀 / 形状」放行:标识符后紧贴 `; , ) :`、形如 `X(y)`、以 `{ ( [` 结尾、以 `env.` `vault` `...` `<` `%` `$` 开头的值,整体当代码放行,真口令因此被原样输出。现在改成**整词白名单**:

**引用形态**(`judgeValue`;不匹配任何一种就当口令):

1. 空串;遮蔽串(`****` `xxxx`);字面量 none/null/undefined/true/false/nil(不分大小写,整词);完整的合法占位符;≤12 位的单个纯小写词(含连字符;已知缺口,见 §7)。
2. 变量引用:`${NAME}` 任何语境;`$UPPER_ENV`(纯大写字母,或带下划线的 UPPER_SNAKE;**大写加数字而没有下划线的 `ABC123XYZ9` 更像口令,不算**)、`$lowerword`(只有字母下划线、无数字)、`$(命令` **只在 shell 语境**(运算符 `=` `:=`)——yaml / ini 里的 `$` 是字面字符;带数字的混合大小写 `$Xyz…` 任何语境都不放行;不带路径后缀。被引号截断的模板表达式(`${placeholder(`)放行。
3. 环境访问(**区分大小写、整词**):`process.env` / `import.meta.env` / `os.environ` / `os.getenv` / `ENV` / `getenv` 等,后接可选的 `.名字`、`[`、`(` 截断残片;配置属性路径 `env.` `config.` `settings.` `secrets.` `vault.` + 名字。**名字段**只认 `UPPER_ENV`(同上)或「只含字母下划线、不带数字」——带数字的段更像口令。
4. 类型名:首标识符在封闭集合里(string、str、number、int、bool、Record、Map、Array、Optional、List、SecretStr…),其后只允许类型括号、逗号、同集合的词,不得含数字。
5. 调用:`X(y)` **不再自动放行**。callee 路径不含数字,并且:没有参数 / 未闭合(`createToken(`),或最后一段以取值类动词开头(get/read/load/fetch/resolve/lookup/prompt/input/decrypt/generate/random/…)且参数是单个无数字标识符 / UPPER_SNAKE / `$VAR`(`getToken(user)`)。以未闭合括号结尾的代码残片(无数字、无引号:`, R(`)放行。
6. `<闭合占位词>`、`{{ 名字 }}`、`%VAR%` / `%s` / `%(name)s`。

**剥尾部标点**:无引号的值先生成候选 c0=原值、c1=去尾 `; , : \`、c2=再去 `) ] }`、c3=再去 `( { [`;**任一**候选是引用形态就放行(`string[];` `getToken(x);` `Map<string,`);全不是 ⇒ 口令,**只脱敏 c3 这个核心**,尾部标点留在输出里(`connect(host=h, password=[[REDACTED:credential]])`,语法不被破坏)。引用形态是封闭集合里的整词,标识符本身(口令样子的 `Hunter…`)不在其中,所以「口令 + 标点」不会被放行。取舍:口令自身恰好以 `; , : ) ] }` 结尾时,这些尾部标点(通常 1-2 个字符)会留在输出里。

**默认值字面量**:值被判为引用(也包括不足 8 个字符的短引用 `env(` `ENV[` `$(echo`)后,若它停在未闭合的 `(` `,`、是环境访问(`ENV[` `os.environ[` 的 `[`、`process.env.X`)、是 `$(…`,或后面紧跟默认值运算符(`||` `??` `or` `:-`),同一语句里(到 `;` / 行尾 / 配平的 `)`,≤256 字符;**字面量必须在同一行闭合**,三元、反引号都算)长度 ≥8 且不是引用形态 / 环境变量名的字符串字面量与命令替换里的裸词照样脱敏;值被判成口令而停在 `(` 时(`getattr(settings,`),函数名脱敏之外参数里的字面量也照扫;类型标注后跟调用(pydantic 的 `Field(default=…)`)同理(键名等号后接 `os.getenv("X", "默认值")` 一类)。阶段 id `ref_trailing_literal`。

**原视图补扫**(`view_orig_union`):口令里的字面 `\t` `\n`、JSON 里的 `\\t` 在 JSON 空白视图里变成真空白,值在那里被截断(短于 8 个字符就整条不匹配,否则后半段漏出)。现在 JSON 空白视图改过文本时,值类规则在原视图上再跑一遍取并集。pass2 与 `--check` 走同一条路径,所以「原视图命中、JSON 空白视图没命中」也判残留。两个边界:

- 原视图命中若**以转义空白开头**(`NAME=` 剥掉占位符后值从 `\n` 开始),丢弃——那在 JSON 空白视图里是「值为空」;
- 原视图补扫里,**无引号**的值仍在转义的 `\n` `\r` 处截断(与真换行同口径,否则会吞掉下一行;`\t` 不截);截断点之前若是像口令的短头部(<8 个字符,`Kx8q2\nLm9pQz`)则整值脱敏,若是引用 / 标点残片(`{` `)`)则当作「值为空」;**例外(B09e,`placeholder_tight_head`)**:值紧贴占位符、且短头部整体只是一对闭合的短括号实参(`^\([\w.$-]{0,5}\)[;,]*$`,如 `(ab);`)时,那是占位符后面剩下的尾巴,当作「值为空」;其它短头部(`占位符Kx8q2\n…`)照旧整值脱敏。已知残余(P1-A.3 订正):**真占位符**(pass1 自己产出的形态)后面的 `(ab);\n后半段` 仍按设计当作「值为空」放行(第二遍复扫第一遍的输出要靠它)。但原文自带的占位符标记现在会被 `--stdin` 与 collect 先拆开,拆开后的中性化标记不占位,同一形状整值脱敏、后半段不再漏(§3.4)。此前记的「`signals collect` 先拆开标记所以走不到」不准确:实测拆开前后引擎都不识别中性化标记,后半段两条路径都漏。代价(已知缺口):截断点之前已有 ≥8 个字符的无引号口令,里面的字面 `\n` / `\r` 之后的部分不会脱敏;带引号的值、以及 `\t`,全部覆盖。引用式候选(`'^NAME='`)在原视图补扫里不判(没有真换行,引号奇偶不可靠),结构上是引用式的交给 JSON 空白视图那一遍。

**占位符间隔**(`placeholder_boundary`):见 §3.1 第 2 条。pass1 只脱敏了一半的拼接值(`NAME=[[REDACTED:credential]]"值"`)现在由 `cred_assign` 把后面的值照常脱敏,不再被 `occupied` 判成干净。

**两遍一致**:引用式的开引号奇偶计数**跳过将被 `cred_assign` 脱敏的值内部的引号**(第二遍里那些值已经是占位符,没有引号可数),两遍的判定因此等价;`apply(apply(x)) == apply(x)` 与 `pass2(apply(x))` 干净由 `test/redact/b09c.test.ts` 与 `envref.test.ts` 钉死。

**其它值写法**(`cred_assign_ext`):反引号值(JS 模板串、Go 原始字符串;须同行闭合且内容不以空白开头);同行三引号值;类型标注 `键: 类型 = 值`(类型部分 ≤40 字符、不含引号,之后任意写法);引号拼接(`NAME=ab"值"`、`NAME="ab""值"`、`NAME="ab"值`:无引号段紧贴引号段,或两个引号段相邻,或短的无空白前缀引号段后接无引号段;含 JSON 转义引号 `\"`;引号段必须闭合);`passphrase` 键的无引号多词短语(≥2 词且 ≥12 字符,到行尾 / `;`)。引号里带空格的整串(`password = "多个词"`)本来就由 `cred_assign` 的引号分支整串脱敏。

**线性**:`cred_assign` 双引号值分支里的反斜杠串用「前瞻捕获 + 反向引用」一次吃掉(原子化),64K 个反斜杠不再二次增长;`readUnit` 找收尾引号 / 行尾只在 512 字符窗口内,词内查找不越过词尾,外围收尾字符最多剥 64 个;`lastIndexOf` 回看有界。

阶段 id 汇总(变异自检逐个禁用,各有专属种子):`view_orig_union`、`ref_tail_punct`(禁用 ⇒ 额外接受旧 CODE_SHAPE / CALL_CHAIN)、`ref_boundary`(额外接受旧 NON_SECRET_START)、`ref_flag_strict`(额外接受旧 FLAG_REF)、`placeholder_boundary`(旧 occupied 判定)、`ref_trailing_literal`;规则 id:`cred_assign_ext`。

### 3.3 真实会话样本上的两遍一致(B09e)

真实 Claude 会话样本(A6)暴露的三类形状,合成复现见 `test/redact/b09e.test.ts` 与 `test/signals/redact-real-shapes.test.ts`:

1. **值区间吞掉转义换行的反斜杠**(阶段 `span_escape_tail`)。JSON 空白视图把转义空白的反斜杠换成空格,值类规则的字符类会把这个空格当成值的一部分,区间连反斜杠一起被替换,输出成了 `占位符next`:转义丢了,上下两行粘成一行,第二遍把后一行当成值(授权头的 `Bearer 值\n  if (…Bearer ${secret}…)`、shell 的 `'^NAME='路径\n…`)。现在 `Engine.runRules` 在区间映射回原文坐标后,若区间尾部是反斜杠串、且紧随其后的字符是 `n` `r` `t`,就把这串反斜杠留在区间外(转义保持完整)。**不收缩转义引号**(`\"`):opus 对抗评审实测,收缩后 `Bearer 伪值\"口令\"` 一类写法的 `Bearer` 被占位符取代、口令失去锚点而漏出(原先靠残留的裸引号 fail-closed)。代价:口令真以反斜杠结尾且后面紧跟 n / r / t 时多留 1 个字符。
2. **占位符后面的短尾巴**(阶段 `placeholder_tight_head`)。第一遍只替换了调用名,输出里留下 `占位符(ab);\n…`;第二遍原视图补扫把 `(ab);` 当成「像口令的短头部」整值脱敏,JSON 空白视图却因 <8 个字符放行,两个视图不一致。现在值紧贴占位符且短头部是闭合的短括号实参时不再套用短头部规则(见 §3.2 的例外);同一阶段还让「值紧贴占位符且 <8 个字符」时调用实参里的字面量照常判(`占位符(ab, "口令")`、`占位符(ab)("口令")` 此前整个漏过)。新增放行形态只有这一种(闭合括号、括号内 ≤5 个简单字符,与 JSON 空白视图按长度契约本来就放行的东西一致);`占位符("长字面量")`、`占位符(长实参)`、`占位符(ab)口令`、`占位符口令` 仍脱敏(各有专属种子)。
3. **复扫**:第一遍输出再被 JSON 转义一层(落盘后的信号文件)后须仍然干净。形状 1 的行粘连是已定位的根因;`redact --check` 在真实样本上报的 `cred_assign_ext`(多层转义引号赋值)没能在合成数据上独立复现(大量带前后代码、同行多赋值、占位符与转义引号相邻、单层与多层转义换行混合的变体全部一致),待主代理用真实样本复核。

### 3.4 §7 残余缺口清理(P1-A.3)

逐个缺口:先写会失败的合成复现(`test/redact/p1a3.test.ts`),再修;修不了的留 `known_gap` 并写明理由。

**1. `--stdin` 与 collect 共用同一个「先拆占位符标记」预处理。** 共享函数 `neutralizePlaceholderMarkers`(`src/redact/placeholder.ts`):`[[REDACTED:` → `[[ REDACTED:`。`redact --stdin`(应用路径)调用它;`signals collect`(`src/signals/pipeline.ts` 的 `makeExcerpt`)仍保留自己的一份同语义代码——本块无权改 `src/signals/**`,已登记「待主代理:让 pipeline 改 import 共享函数」;防漂移靠测试(spy 断言 `makeExcerpt` 传给 `apply` 的字符串与共享函数输出一致,另有短输入上摘录等于 `apply(neutralize(x))` 的性质测试)。

- **`--check` 不拆标记。** 它复扫的是 collect 的输出(信号文件),里面的合法占位符必须按占位符看;拆开等于换了视图,与 collect 末尾的 `pass2(excerpt)`(同样不拆)不一致。代价:拿 `--check` 去扫**未经处理的原文**时,伪造的 ASCII 占位符照样豁免(`--check` 的定位是复扫可信输出,不是审计原文)。
- **命令行为变化:** `redact --stdin` 输出里,**输入中原本就有**的占位符变成 `[[ REDACTED:…]]`(多一个空格),第一遍新产出的仍是 `[[REDACTED:…]]`。与 collect 摘录的行为相同。
- **实测与原记述相反的一点:** 缺口登记时说「`--stdin` 不拆所以后半段漏、collect 拆了所以没事」。差分实测(6 种前缀 × 6 种短实参 × 5 种连接 × 3 种后接,共 540 种拼接形状)显示:拆开后的中性化标记在引擎里原本**不被识别**,`NAME=[[ REDACTED:credential]]口令` 一类紧贴 / 紧贴引号的形状在 collect 视图里反而**漏**,`--stdin`(真占位符)不漏,共 108 种。所以只在 `--stdin` 加预处理会让 `--stdin` 退化,必须同时修引擎。
- **引擎里的中性化标记**(阶段 `placeholder_neutral_marker`):`[[ REDACTED:<类型>]]` 在视图里与合法占位符同样被剥掉(所以它把口令从中间切开、或贴着口令时,规则看得到口令)。但它**不占位**:`placeholderGap` 的「值的位置已被占住」只认合法占位符,因为中性化标记是原文自带、可以伪造的(opus 评审实测:若与合法占位符同样判 `occupied`,中性化标记后面隔着空白的口令会拿到豁免,collect 路径因此回归泄漏;已改正并有专属反例)。紧贴值的中性化标记只多一个待遇:值不足 8 个字符时调用实参里的字面量照判(`NAME = 标记(ab, "口令")`)。值被判为口令且紧贴标记时,**区间连标记一起吞掉**(输出 `NAME=占位符`,不留拆开的残片;否则 collect 的 300 码点摘录截在残片中间时第二遍报残留、整条信号被丢)。类型位只允许封闭集合 `KNOWN_PLACEHOLDER_TYPES`(= 规则表产出的 13 个类型,测试对账),恰好一个 ASCII 空格;类型位夹带数据(`[[ REDACTED:aqzx…]]`)拿不到剥离(`gap.neutral_open_type`)。
- **剥离必须原文逐字节如此**(阶段 `placeholder_raw_exact`,同时适用于合法占位符):视图里「看起来像」不算。全角括号(`［［REDACTED：…］］`)、同形字、`\u005b` 转义等经归一化 / 解码才变成标记的写法不再被剥、不再豁免,里面夹带的数据照样脱敏(opus 对抗评审发现的**现存**绕过,stdin 与 collect 都受影响)。配套去掉了 `PH_WHOLE`(「整个值就是占位符」当引用):合法占位符在视图里早已被剥掉,走到那里的只可能是这类伪造串。
- 已知残余:**真**占位符的类型位仍是开放集合 `[a-z_]{1,24}`(契约 `PLACEHOLDER_SOURCE` 如此定义;收紧会影响契约使用方,列「待主代理」);类型位里是纯小写字母的数据与 `gap.word_password` 同源。

**2. 授权头里 `Bearer` 后直接跟引号。** `cred_authz` 的值前允许一个开引号:转义引号(`\"` `\'`,任意层)或紧跟字母数字的裸引号;`cred_bearer` 同。裸引号要求后面紧跟字母数字,是为了不把源码里 `'Authorization: Bearer ', R(…` 这类代码当成值(自扫描会命中)。值前有转义开引号时,收尾 `\"` 的反斜杠留在区间外(输出仍是 `Bearer \"占位符\"`,JSON 转义不被破坏)。与 B09e「不收缩转义引号」不冲突:那条管的是值尾的收缩;`Bearer 伪值\"口令\"` 仍是 fail-closed 或不含口令(测试钉住)。

## 4. 占位符

- 格式 `[[REDACTED:<type>]]`,`<type>` 只取 `[a-z_]+`,产出时来自上表的类型。
- pass2 先剥掉合法占位符再扫。**合法 = 类型长度 1..24 且完全符合契约正则**;所有其它形态(嵌套 `[[REDACTED:[[REDACTED:x]]]]`、大写、空类型、类型位里塞数据、超过 24 个字符、中间夹零宽字符)**都不剥,按普通文本继续扫**,拿不到任何豁免,里面藏的秘密照样被抓。
  这是契约正则 `[a-z_]+` 的一个**子集**(多了长度上限 24),目的是堵住"用超长类型位夹带数据"的通道;见 §9 的歧义 1。
- 剥离用空串替换。所以 `sk-…[[REDACTED:x]]…` 这种被占位符从中间切开的秘密,剥离后拼回再扫仍会命中。
- 值类规则(`cred_assign`、`cred_cli_flag`)对「`NAME=` 后面夹着占位符」另有判定,见 §3.1 第 2 条:剥掉占位符后残留的 `NAME=` 加后面的无关词,不再被当成赋值。
- 中性化标记 `[[ REDACTED:<已知类型>]]`(`signals collect` 与 `redact --stdin` 拆开原文占位符之后的形态)按同样方式剥离;剥离一律要求原文逐字节如此,见 §3.4。
- 词表里的词、任何规则都不会命中到合法占位符内部(它在匹配前已被剥掉),所以 `pass1` 是幂等的:`pass1(pass1(x)) === pass1(x)`(有专门测试,含"词表里的词恰好是占位符类型名"的情形)。

## 5. 解码层

- **base64 / base64url**:`[A-Za-z0-9+/_-]{20,}` 段,依次尝试丢掉前 0..3 个字符再解码(前面多出的字符会让 4 字符对齐错位);在原视图和压缩视图上各做一次(折行的 base64)。
- **base32**:≥32 个 `[A-Z2-7]`(或 `[a-z2-7]`)字符(阶段 `decode_base32`)。
- **hex**:≥24 个十六进制字符(阶段 `decode_hex`)。
- 解码结果必须"像文本"(≥90% 可打印、无大量替换字符)才继续扫;二进制垃圾直接丢弃。单段上限 16 KiB。
- 解码出来的文本整体递归扫描(同样有归一化、压缩、再解码)。**深度上限**:pass1 为 2,pass2 为 3。解码总量上限 = 输入长度的 4 倍 + 4 KiB,候选段上限 4096,超限一律 fail-closed(`error`)。
- 命中时:整段编码串替换成占位符(无法部分替换)。

## 6. fail-closed 与退出码

| 情形                                                        | `apply` 结果                      | 命令退出码 |
| ----------------------------------------------------------- | --------------------------------- | ---------- |
| 全部干净                                                    | `{ ok:true, text }`               | 0          |
| pass2 在 pass1 输出里仍有命中                               | `{ ok:false, reason:'residual' }` | 3          |
| 扫描器抛错、输入超过 `max_input_chars`、解码体量/候选段超限 | `reason:'error'`                  | 3          |
| 超过 `timeout_ms`                                           | `reason:'timeout'`                | 3          |
| `--check` 有命中(给 A10 用,不是 fail-closed)                | —                                 | 1          |
| 用法错误                                                    | —                                 | 2          |

`pass2` 遇到异常/超时返回 `clean:false` 加一个合成命中(类型 `scanner_error`,规则 `scan_timeout` / `scan_error`),不抛;`pass1` 遇到异常/超时抛 `RedactError`。**任何一种都不会放行文本。**

### 超时是怎么实现的(以及做不到什么)

Node 的正则不能被抢占,本仓 lint 又禁止 `worker_threads`,所以**做不到**"到点强杀一条正则"。防线是三层:

1. 每条规则写成线性:没有嵌套量词;不用"前置 `[..]*` 再找关键词"(改成先找关键词再向后匹配);需要锚点+有界扩展的(email、PEM、JWT)手写扫描,并缓存"已确认没有页脚/没有 `.`"这类事实;失败路径的回溯量有常数上界;值类规则(`cred_*`)不设上限但**匹配总会消费它扫过的文本**(闭合引号可选),所以不会反复重扫。
2. 输入长度上限 `max_input_chars`(默认 65536):即使某条规则退化到二次,也被这个上限框住。
3. 时钟检查点:规则之间、每个热循环每 64 次迭代、每个解码候选段。到点抛 `timeout`。单条正则 `exec` 内部不查时钟,所以最坏情况是"预算 + 最慢一条规则的一次扫描"。

验证:`test/redact/failclosed.test.ts` 对 50 种对抗输入(每种 64 KiB:重复前缀、重复 `@`、`%4`、`\u00`、`-----BEGIN `、长空白、长引号拼接……)逐一跑完整 `apply`,断言(a)有限时间收场,(b)耗时不超过同长度良性文本的 100 倍;另有注入时钟的确定性超时测试。
吞吐实测:100 KB 混合文本 `apply` 约 3–5 MB/s(门槛 1 MB/s);64 KB 普通文本在默认 50 ms 预算内完成。

## 7. 种子集与自检

`src/redact/seeds.ts` 在运行时生成种子,**不写盘**。固定 seed(`0x5eedb09`)的 PRNG,同 seed 两次生成逐字相同。

**仓库里没有任何完整的密钥字面量**:源码里只有前缀、字符表和生成规则;密钥体是 PRNG 输出或低熵重复模式(`a1a1…`),PEM 体、JWT、base64 都在运行时拼装。头部片段(`-----BEGIN`、`eyJ`)可以出现。
`test/redact/repo-scan.test.ts` 用自有扫描器对本块的全部源码、测试、本文档做零豁免扫描,保证这一点。

低熵体是故意的:它躲过高熵检测,所以只有"对应的那条规则"能抓住它,变异自检才能证明每条规则都有用。

### `agent-kit redact --selftest [--mutate]`

- 不加 `--mutate`:跑上表全部判据。召回必须 100%,任何失败退出 1。
- `--mutate`:对**每个规则 id 与每个阶段 id**(共 78 个)各禁用一次,重跑所有 `recognized` / `entropy_only` 种子,要求"变红的种子集合"**恰好等于**种子声明的 `pinned`:
  声明了却没变红(说明种子没钉住这条规则),或没声明却变红(说明种子有未登记的依赖),或某条规则没有任何 pinned 种子,都算失败。
- 输出只含种子 id、规则 id 与计数,**绝不打印种子内容**。

## 8. 阈值与实测

高熵阈值 4.0 比特/字符、长度 ≥24,用种子集 + 本仓与相邻仓库的误报样本标定。随机串命中率(各 2000 次抽样,2026-10-08 实测):

| 字母表                | 24 位  | 28 位  | 32 位   | 40 位   | 64 位 |
| --------------------- | ------ | ------ | ------- | ------- | ----- |
| 大小写字母 + 数字(62) | 约 93% | 约 99% | 约 99%  | 100%    | 100%  |
| base64(64)            | 约 95% | 约 99% | 约 100% | 约 100% | 100%  |
| base64url(64)         | 约 94% | 约 99% | 约 100% | 约 100% | 100%  |
| 小写字母 + 数字(36)   | 约 59% | 约 85% | 约 96%  | 约 100% | 100%  |
| 十六进制(16)          | 0%     | 0%     | 0%      | 0%      | 0%    |

经验熵对短串有系统性低估,所以 24 位随机串压线;小写字母数字和十六进制的字母表小,熵上限本来就低。这是已知取舍,不是 bug:要抓这两类靠上下文规则(赋值、头、前缀)。

## 9. 与契约/计划的差异与歧义(需主代理确认)

1. **占位符类型长度上限 24**:契约的精确正则是 `[a-z_]+`。本实现剥离时用 `[a-z_]{1,24}`,更长的不剥。理由见 §4。所有产出的类型 ≤14 个字符。如果别的块会产出更长的合法类型,需要提高这个上限(`MAX_PLACEHOLDER_TYPE`)。
2. **`timeout_ms` 的口径**:契约写"每条输入的时间预算"。本实现按**每次 pass1 / pass2 调用**各自计时。
3. **`Redactor.pass2` 的失败表示**:契约签名没有失败分支,所以异常/超时表示为 `clean:false` + 合成命中。需要区分原因的调用方用 `RedactorImpl.pass2Detail()`。
4. **种子生成器位置**:计划写 `test/fixtures/redact/seeds.ts`,但 `--selftest` 是 CLI 的运行期功能,生成器必须随 `dist/` 发布,所以放在 `src/redact/seeds.ts`。`test/fixtures/redact/` 不需要。
5. **A10 的扫描入口**:`agent-kit redact --stdin --check [--allow-host <h>]…` 对任意文本做 pass2 复扫:干净 0、有命中 1(只打印规则/类型/偏移)、异常/超时 3;超过 64 KiB 自动分块(块间重叠 2 KiB)。B18 的 `a10-privacy.sh` 可以逐文件喂它。`url` 规则默认名单为空,所以扫全仓时要把仓库里出现的公开主机用 `--allow-host` 列全(本块文件只需要 `github.com`)。
   **已知会命中**:`docs/contracts.md`(B01)里若有非保留域的邮箱/URL 示例会命中;本块自扫描时 B01 的示例用的是保留域,不命中。`pnpm-lock.yaml` 的 integrity 串因带 `integrity` 上下文且长度匹配而放行。

## 10. 命令

```text
agent-kit redact --selftest [--mutate]
agent-kit redact --stdin [--allow-host <host>]… [--timeout-ms <n>] [--overlay <kit.overlay.toml>]
agent-kit redact --stdin --check [同上]
```

`--overlay` 读 `sensitive_words` 与 `internal_domains`;覆盖层读取或校验失败退出 2,**不回显任何覆盖层内容**(它本身就是敏感词表)。
`--stdin` 先把输入里的占位符标记拆开(与 `signals collect` 同一函数,见 §3.4);`--check` 不拆。
`--stdin` 失败时 stdout 为空,stderr 只有 `REDACT_FAIL_CLOSED reason=<residual|error|timeout>`,不含输入的任何片段。
